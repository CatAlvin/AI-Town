# ADR：验收证据推进的开发决策记录

日期：2026-06-26

## 背景

目标是在 `Furry_Medieval_AI_Game_Acceptance_Checklist.md` 下继续推进《绒火与月铃》的本地可复核证据，同时不把真人试玩、真实服务器部署、视频录制或人工签署伪装成已经完成。

## 决策 1：保留轻量可运行版本，不回退到原开源项目复杂栈

- 读取现状：已检查 README、运行脚本、`src/gameData.js`、`src/gameRules.js`、`public/app.js`、验收脚本和当前缺口报告。
- 假设：当前垂直版本的核心价值是中文 2D 冒险、NPC 关系、传闻、战斗、存档和验收证据；继续补证比迁回复杂后端更能稳定交付。
- 影响范围：规则层、前端复用、证据脚本、自动验收报告和中文文档。
- 风险：轻量版本无法直接满足真实 90-150 分钟体量、外部试玩和部署录像。
- 验证：`npm run validate`、`AUTO_ACCEPTANCE_STATUS.md` 和覆盖矩阵同步记录仍缺的外部证据。

## 决策 2：关系、经济和升级逻辑先沉到规则层

- 读取现状：前端曾有本地对话或购买判定，自动测试只能覆盖部分 UI 字符串。
- 假设：共享规则层能降低前端和验收脚本分叉风险。
- 影响范围：`src/gameRules.js`、`public/app.js`、规则测试、证据生成脚本。
- 风险：规则层接口变多后需要防止测试只验证实现细节。
- 验证：关系分支、经济曲线、成长升级和前端静态复用测试都纳入 `node --test`。

## 决策 3：把“人工最终证据”与“本地自动证据”分开标记

- 读取现状：许多清单项同时要求代码功能、截图、视频、外部试玩或部署取证。
- 假设：本地能证明的内容应尽量自动化；必须由真实用户或真实环境完成的内容保持 partial。
- 影响范围：`scripts/acceptanceAudit.js` 的 pass/partial 口径、`QA_SMOKE_REPORT.md`、`ACCEPTANCE_COVERAGE.md`。
- 风险：过度自动化可能误导最终签署。
- 验证：自动验收报告结论固定写明外部试玩、Linux 部署、实机短片、Firefox 实机和最终签署仍缺失。

## 决策 4：发布素材采用自制 SVG 源文件加截图包，而不是引入外部图片

- 读取现状：正式资源目录此前无外部图片，截图包已经有视觉基线。
- 假设：自制 SVG 主视觉和 favicon 能满足源文件、图标和作品集用途，同时避免许可风险。
- 影响范围：`docs/acceptance/presskit/`、`public/favicon.svg`、`public/index.html`、press kit 报告和测试。
- 风险：SVG 主视觉仍需要最终人工美术审查，不能替代商店页审核。
- 验证：press kit 报告校验尺寸、大小、SHA-256 和截图包覆盖；生产审计确认运行时代码无禁用模式。

## 结论

上述决策把每次大改动限定在可验证模块内，并保留风险边界。后续如果要进入最终候选版，应先冻结功能，再补真实试玩、部署、视频和人工签署证据。
